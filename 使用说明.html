1. 系统要求

  • Java 运行环境：JDK 21 或更高版本
  • 操作系统：Windows / macOS / Linux（桌面环境）
  • 依赖库： org.json（JSON 解析）、 org.luaj.vm2（Lua 脚本引擎）

2. 快速开始

2.1 启动游戏

运行 Main 类（通过 IDE 或命令行）。
游戏窗口标题为 "by 6g66gtf"，默认大小 400×340 像素，不可缩放。

如果使用打包好的 JAR，请确保 setting.txt 及所有资源文件位于 JAR 同级目录下。

2.2 基本操作

按键功能
W A S D向上 / 左 / 下 / 右移动玩家
F交互（面对 NPC、按钮时触发对话或动作；在对话框模式中翻页）
Z打开 / 关闭“背包查看模式”（显示主手物品详情）
R重置当前关卡（重新加载地图 JSON）
B调试：在控制台打印玩家当前坐标（X, Y）
移动和交互均在游戏循环中处理（每秒 10 tick）

4. 地图编辑（JSON 格式）

地图文件由根对象 { "events": [...], "content": [...] } 组成，数组元素为以下类型之一。

4.1.1 地图初始化事件

初始化事件写法同5.1

4.1.1 event:{} 示例

[
                "type": "queueEvent", "event": { "event": "playSound", "key": "open" },
                "type": "queueEvent", "event": { "event": "playBGM", "key": "home" },
                "type": "queueEvent", "event": { "event": "DrawMessage", "name": "system", "msg": "你启动了map.txt" }
            ],

4.1.2 通用字段

每个对象必须包含 "type" 字段，取值如下：

block

静态方块

item

可拾取物品

player

玩家初始位置（每图唯一）

entity

交互实体（由 "type1" 区分子类型）

📐 所有坐标均为整数，以格子为单位（1 格 = 60 像素）。视口大小为 5×5 格，玩家始终居中。

4.2 type = "block" —— 方块

字段类型说明
typestring固定 "block"
xint左上角 X 坐标
yint左上角 Y 坐标
wint宽度（格数）
hint高度（格数）
imagestring图片文件路径
isCollideboolean是否有碰撞体积（玩家不可穿过）
isDrawboolean是否绘制（false 则不可见，但仍可能有碰撞）

示例：

{
                "type": "block",
                "x": -1,
                "y": -1,
                "w": 1,
                "h": 7,
                "image": "icon/wall.png",
                "isCollide": true,
                "isDraw": true
            }

4.3 type = "item" —— 可拾取物品

玩家移动到物品所在格时按F拾取，并放入主手（唯一物品栏）。拾取后触发 DrawMessage 事件，显示“你捡起了 <名称>”。

字段类型说明
typestring固定 "item"
xint坐标 X
yint坐标 Y
imagestring图标路径
namestring物品名称（用于条件匹配）
labelstring描述标签（用于条件匹配）
valueint数值（用于条件匹配）

示例：

{
                "type": "item",
                "x": 0,
                "y": 0,
                "image": "icon/diamond.png",
                "name": "钻石",
                "label": "稀有矿物",
                "value": 100
            }

4.4 type = "player" —— 玩家初始位置

每张地图必须且仅有一个玩家对象。

字段类型说明
typestring固定 "player"
xint初始 X 坐标
yint初始 Y 坐标
default-healthint初始生命值（由地图文件定义）
imagestring玩家角色图片路径

示例：

4.5 type = "entity" —— 交互实体

由 "type1" 字段区分具体行为，可选值："message"、"button"、"trigger"。

4.5.1 type1 = "message" —— 对话 NPC

玩家面对该实体按下 F 键时显示多页对话，按 F 逐页翻看，全部显示后自动关闭对话框。

字段类型说明
typestring固定 "entity"
type1string固定 "message"
xint坐标 X
yint坐标 Y
namestring对话者名称（显示在对话框顶部）
msgarray<string>多行对话内容（数组每个元素为一页）

示例：

{
                "type": "entity",
                "type1": "message",
                "name": "PC",
                "msg": ["你好！", "欢迎来到世界。", "按 F 继续。"],
                "x": 0,
                "y": 2
            }

4.5.2 type1 = "button" —— 按钮

玩家面对该实体按下 F 键时执行动作列表（顺序执行）。

字段类型说明
typestring固定 "entity"
type1string固定 "button"
xint坐标 X
yint坐标 Y
actionsarray<object>动作对象列表（见下方）
动作对象（Button）

每个动作必须包含 "type"，取值及参数：

  • "queueEvent" —— 触发事件
    需要子对象 "event"，其中 "event" 字段可取：
    • "draw_msg"：显示单条消息，需提供 "name" 和 "msg"。
    • "playSound"：播放一次短音效，需提供 "key"（音频配置中的键名）。
    • "playLoopSound"：循环播放音效（会停止当前 BGM），需提供 "key"。
    • "playBGM"：切换背景音乐（停止所有音频），需提供 "key"。
    • "stopAll"：停止所有音频（无额外参数）。
    • "setPlayerHealth"：设置玩家生命值，需提供 "health"（整数）。
    • 任意其他字符串：作为 test 事件，将该字符串加入事件日志（可供触发器条件检测）。
  • "setBlock" —— 修改方块属性
    需提供 "set": {, "x", "y", "isCollide", "isDraw", }。
  • "LuaScripe" —— 执行 Lua 脚本
    必须包含 "script" 字段，值为脚本文件路径（相对于项目根目录）。

Button 完整示例：

{
                "type": "entity",
                "type1": "button",
                "actions": [
                    {"type": "setBlock", "set": {, "x": 3, "y": 3, "isCollide": false, "isDraw": false}, },
                    {"type": "queueEvent", "event": {"event": "draw_msg", "name": "系统", "msg": "按钮已按下"}},
                    {"type": "queueEvent", "event": {"event": "playSound", "key": "bell"}},
                    {"type": "queueEvent", "event": {"event": "custom_event"}},
                    {"type": "LuaScripe", "script": "Lua/test.lua"}
                ],
                "x": 4,
                "y": 2
            }

4.5.3 type1 = "trigger" —— 触发器

自动检测条件，满足时执行动作（无需玩家按键）。
特殊字段 "repeat"（布尔）：true 表示每次条件满足都执行；false 表示仅执行一次（执行后失效）。

字段类型说明
typestring固定 "entity"
type1string固定 "trigger"
xint坐标 X（用于碰撞条件）
yint坐标 Y
repeatboolean是否可重复触发
actionobject包含 "condition" 和 "execute"
action 结构

condition：条件数组（多个条件按逻辑组合）
每个条件对象包含：

  • "type"：可选 "collide", "mainHand", "event"。
  • "logic"：可选 "and", "or", "not"，表示当前条件与前一个条件的逻辑关系（第一个条件忽略 logic）。
  • 附加字段（依 type 而定）：
    • "collide"：无额外字段，检测玩家是否站在触发器坐标上。
    • "mainHand"：检测玩家主手物品，需提供 "name", "label", "value"；若某项不限制，填 "NAN"（字符串）或 -1（数值）。
    • "event"：检测某个事件是否刚发生过（事件名），需提供 "event" 字段。

execute：动作数组）
支持：

  • "queueEvent"：支持 "draw_msg", "playSound", "playLoopSound", "playBGM", "stopAll", "setPlayerHealth"（不支持自定义 test）。
  • "setBlock"：需提供 "set" 对象，包含 "x", "y", "isCollide", "isDraw"。
  • "LuaScripe"：必须包含 "script" 字段，值为脚本文件路径。

Trigger 完整示例：

{
                "type": "entity",
                "type1": "trigger",
                "repeat": false,
                "action": {
                    "condition": [
                        {"type": "collide", "logic": "and"},
                        {"type": "mainHand", "logic": "or", "name": "钻石", "label": "NAN", "value": -1}
                    ],
                    "execute": [
                        {"type": "queueEvent", "event": {"event": "playSound", "key": "bell"}},
                        {"type": "queueEvent", "event": {"event": "draw_msg", "name": "系统", "msg": "条件满足！"}},
                        {"type": "setBlock", "set": {"x": 2, "y": 2, "isCollide": true, "isDraw": true}},
                        {"type": "LuaScripe", "script": "Lua/test.lua"}
                    ]
                },
                "x": 4,
                "y": 3
            }

5. 事件系统

事件用于解耦交互与响应，通过 Events 单例管理。

5.1 内置事件（由游戏自动触发）

事件名（代码中）触发时机参数
DrawMessages对话 NPC 交互name, msg（字符串数组）
DrawMessage单条消息（按钮、拾取、系统提示）name, msg（字符串）
playSound播放短音效key（音频键名）
playLoopSound循环播放音效key
playBGM切换背景音乐key
stopAll停止所有音频无
setPlayerHealth设置玩家生命值health（整数）

5.2 自定义事件（test 事件）

通过按钮的 queueEvent 动作，若 "event" 字段不是上述固定名称，则会被作为 test 事件处理，将事件名字符串写入事件日志（LOG）。
触发器可通过 "event" 条件检测该日志中是否存在指定字符串（检测后会消费该日志条目）。

⚠️ getLOG 会删除日志中所有匹配项，因此同一事件只能被一个触发器消费一次。

6. 音频配置

音频配置文件（由 setting.txt 的 "content" 指定）为 JSON 数组，每个元素定义一种音频。

字段类型说明
keystring唯一标识（用于事件引用）
typestring"sound" 或 "BGM"
filestring音频文件路径（相对项目根目录）

示例：

[
                {"key": "bell", "type": "sound", "file": "sound/bell.wav"},
                {"key": "home", "type": "BGM", "file": "sound/home.wav"}
            ]
  • type = "sound"：短音效，使用 Clip 预加载，可多次播放。
  • type = "BGM"：背景音乐，使用流式播放（SourceDataLine），支持无缝循环，切换时会停止当前并播放新曲。
📌 推荐使用 WAV 格式，以确保 Java Sound API 的最佳兼容性。

7. Lua 脚本接口

脚本可通过 LuaEngine 提供的全局函数与游戏交互。

7.1 全局函数

函数参数返回值说明
getContent()无LuaTable返回当前游戏数据（方块、玩家、实体等）的只读副本。

8. 常见问题（FAQ）

Q：地图加载失败或出现 NullPointerException？
A：检查 setting.txt 是否存在且格式正确；检查地图 JSON 是否包含 "player" 对象；确保所有图片路径存在。
Q：音效无法播放？
A：确认音频文件路径正确，格式受 Java Sound 支持（建议使用 WAV）。若为 MP3，可能需要额外解码库（本引擎未内置）。
Q：触发器条件不生效？
A：检查 "event" 条件是否消费了日志（同一事件只能被一个触发器消费）。建议将自定义事件用于全局状态，而非重复触发。
Q：如何重置玩家位置和地图状态？
A：按 R 键即可重新加载地图，所有状态恢复初始。
Q：如何扩展新实体或动作类型？
A：可在 content.java 中新增 Entity 子类，并在 register.createEntity 中解析；动作可添加新的 Execute.ActionType，并在 Button 或 Trigger 的 myAction 中实现逻辑。

9. 开发与扩展建议

  • 事件驱动：优先使用 Events 发送消息，避免硬编码耦合。
  • Lua 脚本：适合编写复杂的条件判断或临时调试，但注意性能（每次 eval 都会重新解析）。
  • 地图设计：合理使用 Trigger 和 Button 可构建丰富的剧情或谜题。
  • 性能优化：避免在 tick 中执行耗时操作；若需长时间运行，请使用独立线程。
